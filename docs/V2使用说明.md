# 群数据 V2 使用说明

群聊中使用 `/群数据`。仅统计管理员加入本群精华、且识别为完整雀魂终局结算的图片。正常结算和负分结算均录入，文字、过程图和不完整截图不录入。

## 统计周期

- 默认查询**当前周期**。封存前全部数据留在历史周期，两者不会混算。
- `/群数据 周期`：查看周期编号和各周期场数。
- `/群数据 被飞榜 四麻 历史`：查询封存的四麻被飞次数榜。
- `/群数据 个人 "完整昵称" 三麻 历史`：查询封存的个人档案。
- 指定其他周期：追加 `周期=周期ID`。模式、时间范围、最少场次、周期参数可以调换位置。
- `/群数据 原图 214`：记录编号跨周期保留，仍可查看原图。

已知精华来源及同一张旧截图不会因重扫、重新转发或重启被重新计入当前周期。历史昵称别名、确认结果和统计快照独立冻结；取消旧精华也不改写封存数据。永久排除的图片仍保持排除。

封存数据主要来自旧有精华样本；不能把它解释为这些玩家的完整历史战绩。新周期也只代表群精华中的样本。

## 查询

| 命令示例 | 作用 |
| --- | --- |
| `/群数据` | 当前周期三麻、四麻总览 |
| `/群数据 被飞榜 四麻` | 按被飞**次数**排序 |
| `/群数据 被飞率 四麻 5场` | 明确按被飞率排序，至少5场 |
| `/群数据 一位 三麻` | 一位次数榜 |
| `/群数据 一位率 四麻 30天` | 近30天一位率榜 |
| `/群数据 二位率 四麻` | 二位率榜 |
| `/群数据 三位 四麻` | 三位次数榜 |
| `/群数据 四位率 四麻` | 四位率榜 |
| `/群数据 末位率 三麻` | 末位率；末位不等于被飞 |
| `/群数据 场次 四麻` | 出场次数榜 |
| `/群数据 平均顺位 四麻` | 平均顺位榜，越小越好 |
| `/群数据 平均持点 三麻` | 平均终局持点 |
| `/群数据 最高 四麻` | 最高持点榜及对应原图 |
| `/群数据 最低 三麻` | 最低持点榜及对应原图 |
| `/群数据 个人 "游戏昵称" 四麻` | 场次、各顺位次数/比率、被飞和持点极值 |
| `/群数据 最近 5 四麻` | 最近5场完整结算，最多20场 |
| `/群数据 对比 "甲" "乙" 四麻` | 两名玩家在本群精华中的统计比较 |
| `/群数据 同桌 "甲" "乙" 三麻` | 仅统计两名玩家同时出场的对局 |
| `/群数据 玩家` | 查看实际录入的昵称 |
| `/群数据 记录 2` | 第二页图片记录 |
| `/群数据 表格` | 获取在线表格链接 |

被飞指最终持点小于0；0不算被飞，同局可能有多人负分。三麻、四麻独立统计，比率的分母是该玩家在对应周期、模式、时间范围内的有效出场数。昵称来自截图，不等于QQ昵称。

时间范围按**加入精华的时间**筛选，不能当作真实对局发生时间。人工新增行的精华时间使用入库时间，实际对局时间可另填。

## 在线表格

四张表：

1. **统计周期**：当前与封存周期，以及封存清单校验值，由机器人维护。
2. **对局明细**：一行一局，含完整玩家、持点、来源编号和原图附件。
3. **玩家统计**：由对局明细重算，含场次、各顺位次数/比率、被飞次数/比率、平均顺位和持点极值。
4. **同步状态**：上次同步结果、错误及需要处理的冲突。

飞书编辑权限由文档分享设置控制。机器人额外核对修改者身份，仅接受服务器配置中获准的飞书管理员的编辑；默认只接受文档所有者。转发链接不会自动授予编辑权。

### 修改已有对局

在「对局明细」修改模式、完整昵称、整数终局持点、备注或实际对局时间。三麻的四位字段必须留空，所有顺位必须完整且不重复，持点与顺位应一致。非标准总持点按管理员人工确认处理。不会根据末位自动补负分，也不会把生僻字替换为相似名字。

- `确认状态=已确认`：纳入统计。
- `确认状态=待核对`：保留记录，暂不纳入统计。
- `确认状态=停用`：软删除，不纳入统计，原图和审计保留；改回“已确认”可恢复仍有效的当前来源。

**不要直接删除整行**。为防止误删和无法核实删除者，物理删除的在线行会按本地数据重建；要删除统计样本，请把确认状态改为“停用”。取消QQ精华后，该局在当前统计中停用，封存周期不变。

错误的半局数据不会覆盖已确认结果。查看该行「同步状态」，修正整局后再等待同步。封存行及稳定ID、周期、群、精华来源、原图等系统字段由机器人维护，不能靠改这些字段挪动记录。

### 人工新增

在对局明细新建一行：

1. **对局ID留空**；群标识、周期ID可以留空，系统填入当前群和当前周期。
2. 模式填 `3` 或 `4`；填写所有顺位的完整昵称和最终整数持点。
3. 上传**一张原始完整结算截图**。管理员应亲自核对，不能用过程图或虚构数据。
4. 将确认状态填为 `已确认`，系统校验通过后生成稳定ID并重算统计。

同一完整结果去重。已封存的同图不能通过人工新增重新进入当前周期。人工新增来源不依赖QQ精华保留，后续QQ群精华扫描不会删掉它。

### 同步频率与冲突

默认每 **600秒**同步一次。修改不是即时到达；管理员可发 `/群数据 同步更新` 提前同步，通过 `/群数据 同步` 查结果。

如果同一局在线和机器人两边都被修改，系统保留双方数据并标注冲突。核对原图后，在该行「冲突处理」填写 `采用在线` 或 `采用机器人`。不能只看行号合并，系统始终按稳定ID对应。

玩家统计不能作为独立真相直接修改。改总次数或比例会被按明细重算还原；没有有效对局的旧统计行会标记为0场。已封存周期不可直接修改。

接口失败时原有命令继续使用本地数据库，重试不会清空统计；失败、校验错误和同步冲突可在同步状态及管理员命令中查看。普通榜单卡片不显示检查时间。

## 管理员命令

- `/群数据 时间`：当前周期数据截至、最新三麻/四麻被飞、检查时间、程序入库时间。
- `/群数据 时间 历史`：封存时的检查信息。
- `/群数据 同步`、`/群数据 同步更新`：在线同步状态/手动同步。
- `/群数据 更新`：立即安排检查QQ精华变更，识别在后台进行。
- 旧有开启、关闭、待确认、核对、确认、忽略、修正、重识、合并、取消合并命令继续保留，封存数据不可修改。

管理员操作只接受明确命令；AI可以查询当前/历史榜单和说明，不替用户确认、改写或停用对局。
