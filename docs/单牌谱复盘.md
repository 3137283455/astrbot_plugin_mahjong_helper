# Mortal 4.1b 复盘与批量趋势

把游戏内复制的完整牌谱链接发给机器人：

```text
/复盘 完整牌谱链接 开局南家
```

也可使用 `/雀 复盘 完整牌谱链接 开局南家`。链接和席位可以换序。开局东、南、西、北家分别对应本场开始时的席位；不要填写后来轮庄时的位置。只发链接会让你补选，5分钟内回复 `/复盘 南家` 即可。

当前只支持四麻东南战，使用在线 Mortal 4.1b。无需提供雀魂账号密码，也不使用魔搭。在线服务需要从牌谱链接获取完整对局。

## 查看结果

任务提交后立即回复编号和前方任务数，按提交顺序在后台排队。完成后在原群里真正@发起人并发送卡片；从私聊发起的任务只回复原私聊。失败或需要人工验证时也通知同一位发起人。没有必要反复发相同链接。

消息会同时附上原始输入链接、完整逐巡复盘链接，以及卡片中各分歧的具体定位链接，点击可直接进入对应本场和决策。官方报告链接通常保留15天；机器人会另外保存报告与卡片。

排队和分析期间，何切、群数据、娱乐、点歌等其他入口继续处理，不需要等复盘完成；只有复盘任务之间串行排队。浏览器运行于独立进程，报告解析、保存和卡片生成均不占用消息处理线程。取消任务不会影响其他功能，重试任务重新排到队尾。

| 命令 | 用途 |
| --- | --- |
| `/复盘 状态` | 当前任务进度或失败原因 |
| `/复盘 结果` | 重看总览卡片 |
| `/复盘 分歧` | 查看模型选择差异较大的前8个决策 |
| `/复盘 分局 南2` | 查看南二局各本场统计及前8个分歧 |
| `/复盘 记录` | 本人在当前会话最近5个任务 |
| `/复盘 取消` | 取消等待或正在运行的任务 |
| `/复盘 重试` | 重试未完成的任务；已有上游编号时继续取报告 |
| `/复盘 帮助` | 查看简要用法 |

## 多条牌谱与汇总

每行填写一条链接及该场开局席位，最多10条；不同场次席位可以不同：

```text
/复盘 批量
第一条完整链接 开局西家
第二条完整链接 开局南家
```

也可用 `/雀 复盘 批量`，保留换行。Mortal报告链接本身包含分析席位，可以不补席位。机器人返回B开头的批次编号；后台依次分析，完成后只推送一张汇总卡片，并附每一场的逐巡链接。

`/复盘 状态` 查看最近批次进度；`/复盘 汇总` 随时查看已取得的结果；`/复盘 取消` 取消该批尚未结束的任务，保留成功报告。也可明确输入 `/复盘 汇总 B批次编号`。要看单场分歧，用汇总消息中的单场编号：`/复盘 分歧 单场编号`。

汇总一致率 = 所有成功报告的一致决策数之和 ÷ 评估决策数之和。不是百分比简单平均。失败、取消的场次不计入；变化显示相对上一份成功报告的百分点。手动提供的链接按提交顺序绘图，不擅自认定为同一玩家或按真实日期排序。

## 最近N场入口

`/复盘 最近 玩家UID或完整昵称 5 玉`，数量1～10，默认5；金、玉、王为可选后缀，默认金之间及以上四麻东南战。未填玩家时使用已有主绑定。取得列表后按目标UID确定每场实际席位，再按时间从早到晚生成批量趋势。

昵称不唯一时要求确认UID；对局列表受到CAP授权或限流限制时，明确说明尚未提交任务，并建议手动提供链接。此入口不承诺能绕过牌谱屋的访问限制，也不会编造最近对局。

默认操作当前会话、本人的最近任务。命令末尾可加任务编号，例如 `/复盘 结果 123456abcdef`。群聊自然语言请求请@慧慧，私聊可直接说“分析这条牌谱，开局南家”。

一致率为“一致决策数 ÷ 评估决策数”；并非每次摸打都计入评估。分歧不等于实战失误，不提供虚构的损失点数。Rating 是模型参考指标，不是群数据综合评分，不宜跨模型版本比较。

## 在线站点需要人工验证时

配置电脑工作端后，电脑上的专用浏览器会等待管理员正常完成验证。该任务继续保留在队列中，通过后自动提交与回传，不需要群友重新发送。电脑离线或休眠时暂停取任务，服务器其他功能不受影响。

自动提交受站点网络、人机验证、限流影响。机器人会明确说明原因，不会把失败当作分析成功。

1. 打开 <https://mjai.ekyu.moe/zh-cn.html>。
2. 填写同一条牌谱，选择正确席位，正常完成站点验证并提交。
3. 报告生成后复制地址栏的报告页面链接，发送 `/复盘 报告页面链接`。

机器人会读取报告，校验席位、版本和逐巡总计，生成同样的卡片。支持该站 `task=...` 的报告链接及 `/report/任务号.json` 链接。当前只使用官方4.1b，其他模型报告不采用，请在原站选择4.1b后提交。本站报告通常只保留15天，成功导入后机器人会保存本地副本。

## 部署说明

浏览器运行环境与 AstrBot 分开，默认 `/bot/mahjong-replay-worker`，包含 `.venv`、`browsers` 和本插件的 `replay_worker.py`。插件启动任务时自动同步执行文件，更新插件后无需手动复制代码；该目录需要运行AstrBot的账号可写。Playwright 不安装到 AstrBot 主环境。

SQLite任务库、报告、卡片位于插件数据目录的 `replays/`，与群数据、何切题库分开。每位用户在同一会话同时1个单场或批次，全局同时只分析1场，最多接收30个未结束场次。重启可恢复任务；同一链接、席位和模型的成功报告复用缓存。

`replay_backend=pc` 使用电脑工作端；服务器网关只监听127.0.0.1，经专用受限SSH账号连接。电脑凭据、私钥、浏览器配置均在本机私有目录；不会上传GitHub。Windows登录后自动运行，断线自动重连，异常退出由任务计划自动重启。电脑不加载任何模型，官方4.1b结果经服务器再次校验后才入库。详情见 [电脑工作端](../pc_worker/README.md)。

实现参考 [majsoul-mortal-rating](https://github.com/Acet1cAcid/majsoul-mortal-rating) 的在线复盘思路，浏览器适配、持久化任务、校验和卡片独立编写；不包含验证码解题或点击绕过功能。分析引擎和在线服务见 [mjai-reviewer](https://github.com/Equim-chan/mjai-reviewer) 与 [Mortal在线复盘](https://mjai.ekyu.moe/zh-cn.html)。

具体手牌定位使用公开的 [KillerDucky UI](https://github.com/killerducky/killer_mortal_gui) `hand`／`ply`参数，按报告中的原始事件与评估条目匹配；无法匹配时只提供整局链接，不编造定位。
