# PerkRadar 独立服务维护

服务目录 `/bot/perkradar`，凭据在 `deploy/client.json` 和权限受限的 `ecosystem.json`；数据在 `data/deals.db`。默认只监听 `127.0.0.1:38471`，不用开放公网端口。

初装上游提交 `ef81e9cc3721c06407c3545639e77ecabf92712b`。上游提交的工作流 YAML 使用 CRLF，而自带检查器按 LF 解析；部署只统一了这些文件的换行，未改抓取或数据库逻辑。检查过的生产构建使用独立测试数据，生产库只包含真实抓取结果。

管理入口：`/bot/AstrBot/.venv/bin/python /bot/perkradar/deploy/manage.py 操作`。

- `status`：本地已装提交、进程和内存，不打印令牌。
- `check`：只比较上游 main 提交，不下载或更新生产，也不向群发送消息。
- `backup`：SQLite 一致性备份及配置备份，输出备份目录。
- `stage 完整提交SHA`：在独立目录下载并运行测试、lint、类型检查、生产构建。构建限制CPU和内存，日志在deploy目录；生产不切换。
- `activate 完整提交SHA`：仅接受有READY标记的候选，先备份，再只停止本服务、切换并验证API。失败自动恢复旧程序和匹配数据库。
- `rollback 完整备份目录`：停本服务，保留故障库，恢复对应程序、配置与一致性数据库。不要把旧程序直接指向已迁移的新库。
- `selftest`：在临时数据库副本中验证WAL备份和恢复，不更改生产数据。

新版本的维护说明、API和数据迁移仍需审核。脚本不盲目自动升级，不替代兼容性评审；分支最新提交也不必然适合生产。全新候选上线前还应在独立端口、独立数据库副本中验证其API契约。

普通群命令不能调用此脚本。AstrBot插件更新只更新Python适配层，不顺带更新PerkRadar、AstrBot或NapCat。群推送默认关闭，升级与重启不补发旧条目。页面收藏和已领属于各浏览器，机器人没有伪造跨端同步功能。
