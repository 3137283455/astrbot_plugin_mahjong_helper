# 群数据：QQ群精华雀魂统计

独立 AstrBot 插件，供 NapCat / OneBot v11 的QQ群使用。只录入精华消息中的**完整雀魂终局结算画面**，不把所有图片都算作对局。

## 使用

群管理员发送 `/群数据 开启`。后台每约2分钟核对精华列表，新图自动排队，删除精华后同步退出统计。首次精华较多时，下载和识别需要时间；用 `/群数据 状态` 看进度。

| 命令 | 结果 |
|---|---|
| `/群数据` | 三麻、四麻独立总览卡片 |
| `/群数据 被飞 四麻` | 被飞次数榜 |
| `/群数据 三麻 被飞率` | 被飞率，显示次数/出场数 |
| `/群数据 一位 四麻` | 一位次数榜 |
| `/群数据 二位率 三麻 30天 至少5场` | 近30天、至少5场的二位率榜 |
| `/群数据 平均顺位 四麻` | 平均顺位榜，越低越靠前 |
| `/群数据 平均持点 三麻` | 最终持点均值榜 |
| `/群数据 最高 四麻` / `/群数据 最低 三麻` | 各玩家极值榜，附第一条记录的原始结算截图 |
| `/群数据 个人 "昵称 有空格" 四麻` | 各顺位、被飞比例、最高/最低持点及原图编号 |
| `/群数据 原图 123` | 查看本群记录 #123 的原图 |
| `/群数据 玩家` / `/群数据 帮助` | 游戏昵称列表 / 图片帮助 |

还支持场次、三位、四位、末位和各顺位比率。三麻没有四位榜。模式、指标、天数和最少场次参数可换序；不填模式会分别给三麻和四麻卡片。含空格的游戏昵称请使用英文双引号。

若日麻助手已升级到0.4.12，可在群里@慧慧说“本群四麻谁被飞最多”。AI入口只查询当前群，不跨群、不代替管理员修改数据。

## 统计口径

- **被飞 = 最终持点 < 0**。0点不算；末位不一定被飞，一局也可能多人负分。
- points读取最终持点，不读取旁边 `+45.7` 等段位/精算分，也不读取某一手增减点数。
- 三麻与四麻完全分开。每人的比例分母为该玩家出现在本群已确认精华对局中的次数。
- **这不是该玩家全部实战胜率。** 如果群里只收藏被飞局，数据也会偏向这些局。
- 时间筛选按**加入精华的时间**，不是根据不完整截图猜测的开局时间。
- 玩家按截图完整游戏昵称区分，不把发图者QQ当作截图玩家，不承诺验证账号归属。
- 同字节图片复用识别缓存；相同完整名单、顺位、持点的结果只计一场。极少数不同对局恰好结果完全相同时也会合为一条；无牌谱ID的截图无法绝对区分。
- 率榜允许小样本，但展示分子与分母，支持“至少5场”等筛选；主指标相同显示并列。
- 不统计截图里没有的信息，例如放铳率、和牌率、谁击飞谁或真实QQ归属。

## 本地识别优先

1. 纯文字精华在获取阶段直接跳过，不调用模型。
2. 本地OCR结合终局标题、完整人数、竖排结算版式、顺位和点数校验，先校正侧转的结算截图。昵称还会检查边缘字符，并对全图和结算区域独立读取。
3. 明显非结算图不调用大模型。昵称、负号、人数等不清楚时不自动入榜。三麻默认总持点105000、四麻100000，其他自定义总额保留待人工确认。
4. 必须辅助时只请求 **AstrBot 当前默认的 DeepSeek**。没有单独魔搭配置，不选择魔搭，不自动切换其他模型。服务器使用WorkBuddy反代时，AstrBot服务的自定义请求头应设置 `X-Realm: cn`，固定走国内版。
5. 默认DeepSeek辅助识别会同时看到原图与同图文字区域放大，支持东1/东2提前被飞结束的终局；通常需要两次独立读取一致，并核对本地清晰文字；两次有分歧时再独立读取一次，每个字段都至少两次相同且完整校验通过才录入。仍无法确认的保留待核对。401/403会暂停辅助请求1小时，不把整批图片反复打向不可用接口；本地队列继续。
6. 默认模型不可用、名字不一致、非标准版式等记录保留待确认，管理员可看原图处理。

本地OCR组件是离线文字识别程序，不调用在线大模型。插件在独立环境运行OCR，避免改动AstrBot其他插件的依赖。

## 管理与纠错

只允许本群群主、群管理员、AstrBot管理员执行管理命令，服务端会核查群内角色，无法核查时拒绝修改。普通成员只能查询。本插件不修改、取消或创建QQ精华本身。

- `/群数据 更新`：立即检查精华变化，异步执行。
- `/群数据 关闭` / `/群数据 开启`：暂停 / 恢复自动检查，历史数据保留。
- `/群数据 待确认 [页码]`：显示待处理编号与原因；`/群数据 记录 [页码]` 查看全部图片状态。
- `/群数据 核对 123`：查看识别候选；`/群数据 原图 123` 查看证据。
- `/群数据 确认 123`：核对原图后确认第一份完整识别候选。缺人、缺名、格式不合法的候选不能直接确认。
- `/群数据 修正 123 三麻 "甲=65000" "乙=42000" "丙=-2000"`：按一位到末位完整填入，修正立即更新统计。
- `/群数据 忽略 123`：忽略该图。
- `/群数据 重识 123`：取消人工覆盖，重新排队识别。
- `/群数据 合并 "旧昵称" "新昵称"`：明确两个名字属于同一人时设置别名；同局两个玩家不能合并。
- `/群数据 取消合并 "旧昵称"`：撤销别名，原始结果一直保留。

修改都有本地审计记录。确认或忽略仅作用于本群，不污染其他群。

## 安装

AstrBot 4.28.1+，NapCat开启OneBot v11。插件分支下载：

`https://github.com/3137283455/astrbot_plugin_mahjong_helper/archive/refs/heads/group-data.zip`

安装后，在 AstrBot 工作目录执行下面命令安装本地OCR独立环境：

```bash
python3 -m venv data/plugin_data/astrbot_plugin_group_data/ocr-venv
data/plugin_data/astrbot_plugin_group_data/ocr-venv/bin/pip install rapidocr_onnxruntime==1.4.4
```

安装中文字体 Noto Sans CJK，重启插件。`ocr_python` 留空即可使用以上环境；Windows可在该配置中填写独立环境Python路径。`llm_fallback=false` 可完全关闭大模型辅助，保留待确认记录。

配置中默认没有启用任何群；`initial_groups` 仅供首次部署使用，不能覆盖管理员后来执行的关闭。

数据在 `data/plugin_data/astrbot_plugin_group_data/`：SQLite数据库、原图缓存、可清理的卡片、OCR独立环境。更新插件不会覆盖数据。备份时应保留整个目录，或在暂停插件后备份数据库及原图。
